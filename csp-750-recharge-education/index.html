₹750 claim — installation-flow education spec

Reminding the CSP that this connection needs a 3-month ISP recharge, at the point where it can still change what he does.

Project Dominance · opted-in CSPs only · v1

1. What changes

An education screen tells the CSP that this connection needs a 3-month (90-day) ISP recharge — the condition he accepted when he opted into the new payout structure — and that the recharge has to be photographed and submitted to claim ₹750.

It replaces the current brief, which today says 30 दिन. For an opted-in CSP that screen instructs exactly the behaviour that fails his claim, so this is a correction, not an addition.

2. Where it goes

  • Immediately before the “Create ISP Account” option in the installation flow. Marked New on the Figma board.
  • The same composable is currently rendered twice — as an overlay on s11 and again as the s15 route after the method sheet. Only the first one matters: choosing “खुद से, पोर्टल पर” opens the ISP portal immediately, so anything shown after that is too late to change the recharge duration.
  • Opted-in CSPs only. Everyone else keeps the existing 30-day brief.

3. Copy

Hindi

इस कनेक्शन पर मिलेंगे — ₹{amount}

{duration} का रिचार्ज करने पर

आपने यही तरीका चुना है, इस कनेक्शन का ISP रिचार्ज {deadline} तक के लिए करना है

मैंने समझ लिया है, इस सेटअप में {days} दिन, 100 Mbps का ISP रिचार्ज करना है

English

You get on this connection — ₹{amount}

for a {duration} recharge

You chose this structure — recharge this connection’s ISP plan up to {deadline}

I understand this setup needs a {days}-day, 100 Mbps ISP recharge

The last line is an acknowledge checkbox and stays in first person in both languages.

4. Every number comes from the backend

The amount, the duration and the deadline date must not be hard-coded in the app. They change per CSP and will change again as the policy evolves — none of that should need an app release or wait on store rollout.

ValueExampleNotes
payout_amount750Per CSP. Rendered with the ₹ symbol by the app, not sent as a formatted string.
required_recharge_days90Per CSP. Drives both “3 महीने” and “90 दिन” — see below.
required_recharge_until2026-11-17ISO date, computed server-side from the install date + duration. The app must not do this arithmetic.
is_opted_intrueGates the whole screen. False → existing 30-day brief.
  • Duration is sent once, displayed two ways. The app derives “3 महीने / 3-month” from required_recharge_days. Sending both a months string and a days number invites them to drift apart.
  • The deadline is a date, not a duration. “17 Nov 2026” is checkable against what his ISP portal shows; “90 days” makes him do the arithmetic.
  • Fail closed. If any of these fields is missing, do not fall back to a default — show the non-opted-in brief instead. A wrong number here costs the CSP a real claim, so no number is safer than a stale one.
  • The same values feed the claim popup, the drilldown and the rejection screens. One source, every surface.

Audio dependency. This screen plays isp_recharge.mp3, which says 30 days. Backend-driven text with a hard-coded voice track is worse than either alone — the audio needs re-recording, or muting for opted-in CSPs, before release.

5. Screens to remove

Some education screens in the installation journey are no longer relevant and should be dropped. Each is marked Remove on the Figma board; some are already gone, ignore those.
